# BYOK + 1회 결제 잠금 해제 — 설계 (v2)

작성일: 2026-08-31
개정: 2026-08-31 — 단어장을 서버(KV) 저장으로 변경, 1회 결제 확정, 복습 설계 추가
개정: 2026-09-02 — **Claude 전용으로 전환.** Gemini·OpenAI 지원 삭제(사용자 결정).
이 문서의 "Gemini 우선 온보딩" 관련 서술은 이 시점부터 무효다. 온보딩은
Anthropic 키 발급 안내(가입+결제수단 필요 명시)로 대체되었고, 진입 장벽 상승은
인지한 채 수용한 트레이드오프다. 모델 선택은 Haiku 4.5(기본)/Sonnet 5/Opus 5.

## 배경

기존 구조는 우리 워커가 우리 Anthropic 키로 조회를 대신 호출했다(Pro 모드).
조회 1건당 약 $0.003의 원가가 나가고 서버 캐시가 없어 사용자 수에 비례해
손실이 커진다. ₩3,000 구독자가 월 한도를 다 쓰면 매달 $1.5~3.7 적자다.

이 설계는 그 구조를 버린다. AI 조회는 사용자 본인의 키로만 동작하고(BYOK),
우리는 **$3 1회 결제**로 소프트웨어 기능을 영구 잠금 해제한다. 구독은 없다.

## 핵심 불변 조건

**우리는 어떤 경우에도 AI 토큰을 사용하지 않는다.**

- 영어 단어·구문 조회는 **BYOK로만** 동작한다. 사용자가 등록한 Claude·Gemini·
  OpenAI 키로 확장이 제공자를 **직접** 호출한다.
- **$3를 결제해도 마찬가지다.** 결제는 기능 잠금을 해제할 뿐 AI 사용량·크레딧·
  토큰을 포함하지 않는다. 결제 전후로 조회 경로가 동일하다.
- 워커는 AI 제공자를 호출하는 코드를 **보유하지 않는다.** `CLAUDE_API_KEY`
  시크릿은 삭제하며 다시 만들지 않는다.
- 따라서 조회 원가는 사용자 수·사용량과 무관하게 **항상 0**이다.

조회 한도를 두지 않는 것, 서버 조회 캐시를 만들지 않는 것, 구독 대신 1회
결제를 택한 것이 전부 이 조건에서 나온다. 워커가 단어장 **텍스트를 저장**하는
것은 이 조건과 무관하다 — 저장은 KV 쓰기일 뿐 AI 호출이 아니다.

**사용자 고지**: 구매 화면과 웹스토어 설명에 "AI 사용료는 본인 API 키로 별도
청구됨"을 명시한다. 빠뜨리면 "$3 냈는데 왜 또 돈이 나가냐"는 환불이 생긴다.

## 판매 구성

| 기능                        | 미로그인        | 무료(로그인)      | $3 결제     | 우리 원가 |
| --------------------------- | --------------- | ----------------- | ----------- | --------- |
| 단어 추출·기본 번역         | ✓               | ✓                 | ✓           | 0         |
| AI 단어·구문 분석 (본인 키) | ✓               | ✓                 | ✓           | **0**     |
| 단어 저장 (서버 동기화)     | ✕ (로그인 유도) | **200개**         | 제한 없음\* | KV, ~0    |
| 복습                        | ✕               | **하루 3장 체험** | 전체        | 0         |
| xlsx 내보내기               | ✕               | ✕ (구매 유도)     | ✓           | 0         |

- 저장·복습·내보내기는 서버의 단어장을 쓰므로 **무료여도 Google 로그인이 필요**하다.
- AI 조회와 기본 번역은 로그인 없이도 동작한다. 결제 전후 동일하다.
- \* "제한 없음"은 판매 문구다. 내부적으로 어뷰즈 방지 상한 20,000개를 둔다.
  하루 20단어씩 3년치 분량이므로 정상 사용자는 도달하지 않는다.

무료 저장 한도 **200개**의 근거: 언어 학습자가 하루 10~20개를 저장하면 2~4주
분량이다. 제품 가치를 체감하기에 충분하고, 꾸준한 사용자라면 한두 달 안에
결제 판단 지점에 도달한다. `CONFIG` 상수 하나로 조정 가능하게 둔다.

## 아키텍처

워커는 **라이선스 + 단어장 저장소**다. AI 호출은 하지 않는다.

```
확장 (BYOK) ──직접──> api.anthropic.com / generativelanguage / api.openai.com
     │
     └──> Worker ──> KV
            /v1/me            로그인·구매·단어 수 조회
            /v1/checkout      Stripe 결제 세션 (mode: payment)
            /stripe/webhook   결제·환불 수신
            /v1/words/list    단어장 전체 조회
            /v1/words/save    단어 저장 (한도 검사)
            /v1/words/delete  단어 삭제
            /v1/words/review  복습 상태 갱신
```

모든 `/v1/words/*`는 Google 액세스 토큰 필수(POST, 기존 라우터 스타일 유지).
`verifyGoogleToken()`과 5분 토큰 캐시는 그대로 쓴다.

### 데이터 모델 (KV)

```
user:<google_sub> = {
  sub, email,
  paid: true|false,
  purchasedAt, paymentIntentId,
  wordCount                       // 한도 검사용, words 쓰기 시 갱신
}

words:<google_sub> = {
  "agent": {
    savedAt: 1788147269697,
    ko: "대리인",                  // 기본 번역 스냅샷
    detail: { ... } | null,       // AI 상세 스냅샷 (있을 때만, 항목당 8KB 상한)
    box: 1, nextDue: 1788233600000  // 복습 상태 (Leitner)
  },
  ...
}

payment:<payment_intent_id> = "<google_sub>"   // 환불 역추적
```

- `words:<sub>`는 사용자당 KV 값 하나다. KV 값 상한 25MB, 단어당 상세 포함
  1~2KB이므로 20,000개 상한에서도 여유가 있다.
- KV는 키당 초당 1회 쓰기 제한이 있다. 확장은 저장 요청을 **1.5초 디바운스로
  묶어서** 보낸다. 연타 저장이 유실되지 않도록 클라이언트에 큐를 둔다.
- `detail`은 저장 시점에 로컬에 있으면 함께 올린다. 없는 단어는 복습·내보내기
  시 본인 키로 재조회한 뒤 업로드한다. 이로써 **다른 기기에서도 뜻·예문이
  보인다** — 기존 `chrome.storage.sync` 방식의 기기 간 공백 문제가 사라진다.
- 확장은 서버 단어장을 `chrome.storage.local`에 미러링해 오프라인에서도 읽을
  수 있게 한다. 서버가 원본이고 패널을 열 때 동기화한다.

### chrome.storage.sync는 더 이상 단어장에 쓰지 않는다

항목당 8KB 제한 때문에 약 340개에서 저장이 실패하는 문제가 있었다. 서버 저장으로
전환하면서 이 제약 자체가 사라진다. sync에는 설정(제공자, API 키 여부 등)만 남긴다.

### 기존 저장분 이관

업데이트 후 첫 로그인 시 `chrome.storage.sync`의 `savedWords`를 서버로
**전량 업로드**한다(로컬 `wordDetails`도 함께). 한도를 초과하는 양이어도 전부
받는다 — 사용자가 모은 것을 버리지 않는다. 이후 추가는 한도 규칙을 따른다.
이관 완료 후 sync의 `savedWords`는 지우고 이관 완료 플래그를 남긴다.

## 결제

### 흐름

1. 잠긴 기능 클릭 → 구매 안내 → (미로그인 시) Google 로그인
2. `/v1/checkout` → Stripe Checkout Session **`mode: 'payment'`**,
   `client_reference_id` = Google `sub`
3. `checkout.session.completed` 웹훅 → `paid: true` + `payment:<pi>` 색인 기록
4. 확장이 `/v1/me` 확인 → 잠금 해제

구독 객체가 생기지 않으므로 만료·갱신·유예·Customer Portal이 전부 불필요하다.

### 환불

`charge.refunded` 웹훅 → `charge.payment_intent` → `payment:<pi>` 색인 →
`user:<sub>`의 `paid: false`. **단어장은 지우지 않는다** — 잠기는 것은 기능이지
사용자 데이터가 아니다. 웹훅 구독 이벤트는 `checkout.session.completed`,
`charge.refunded` 두 개뿐이다.

### 한도 규칙

- 저장 가능 조건은 단순히 **`wordCount < 한도`** 다. 상태 플래그가 아니라 개수
  비교이므로, 한도를 넘긴 사용자가 몇 개를 지워 한도 아래로 내려오면 즉시 다시
  저장할 수 있다.
- 이관으로 한도를 초과한 무료 사용자: 기존 단어는 전부 유지·표시하되, 개수가
  한도 아래로 내려가거나 결제할 때까지 추가만 막힌다.
- Saved 탭에 카운터를 상시 표시한다: 무료 `137/200`, 결제 후에는 개수만.

## 복습 설계 (결제 가치의 중심)

현재 구현은 순서대로 넘기는 플래시카드뿐이다. 다음으로 확장한다.

- **카드 흐름**: 단어 제시 → 사용자가 떠올림 → "정답 보기" → **"알았어요 /
  몰랐어요"** 선택.
- **Leitner 3단계**: 모든 단어는 box 1~3을 가진다. "알았어요"면 상자가 올라가고
  다음 복습일이 멀어진다(1단계 매일, 2단계 3일, 3단계 7일). "몰랐어요"면
  1단계로 내려가고 **같은 세션 끝에 다시 나온다**.
- **오늘의 복습**: 세션은 `nextDue`가 지난 단어만 모아 만든다. 없으면 "오늘
  복습할 단어가 없습니다"와 다음 예정일을 보여준다.
- **상태 저장**: `box`·`nextDue`는 서버 단어 레코드에 저장한다(`/v1/words/review`).
  기기가 바뀌어도 진도가 이어진다.
- 기존의 진행률 표시·발음 듣기는 유지한다.
- **무료 체험**: 하루 3장까지 정상 동작 후 잠금 화면 + 구매 버튼. 체험 카운트는
  `chrome.storage.local`에 날짜와 함께 저장한다(클라이언트 검사로 충분).

않는다. 우회가 실제로 퍼지면 그때 재검토한다.

## Stripe 전환 체크리스트

직전까지 만든 것은 **구독**(Price `price_1UAKhV…`, $3/월)이다. 1회 결제로
바꾸기 위해 필요한 것:

**Sandbox (지금)**

1. 새 Product 생성 — 이름이 결제창에 그대로 보이므로 "Snaplingo Pro Unlock"류.
   1회성 Price **$3** (recurring 없음) → 새 `price_...`
2. `wrangler.toml`의 `STRIPE_PRICE_ID`를 새 Price로 교체
3. 웹훅 엔드포인트(`we_1UAKkm…`) 이벤트를 `checkout.session.completed`,
   `charge.refunded` 두 개로 교체
4. 워커 배포 후 테스트 카드로 결제 → `paid: true` 확인 → 대시보드에서 환불 →
   `paid: false` 확인
5. 기존 테스트 구독(`sub_1UALzI…`)은 대시보드에서 취소(정리용, 선택)
6. 구독 Price·Portal 설정은 미사용 상태로 남긴다 — 삭제 불필요

**Live 전환 시**

- Product·Price·웹훅을 라이브 모드에서 다시 생성 (sandbox 설정은 승계되지 않음)
- `rk_live_` 제한 키 발급: Checkout Sessions write 하나면 충분
  (구독 조회가 없어져 Subscriptions read, Portal write 불필요)
- 시크릿 교체: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_ID`

## 기존 배포 사용자 이관

**확장은 웹스토어에 v1.0.3으로 이미 배포되어 있다.** v1.0.3은 액세스 코드
기반 Pro 모드 + Own Key 모드다.

- **오늘 워커를 재배포한 시점부터 v1.0.3의 Pro 모드(액세스 코드)는 이미 동작하지
  않는다** — 새 워커에 해당 엔드포인트가 없다. Own Key 사용자는 영향 없다
  (워커를 거치지 않는다). 새 버전 출시를 서두를 이유다.
- 액세스 코드는 Buy Me a Coffee 멤버에게 수동 발급된 소수다. 별도 코드 경로를
  만들지 않고 **수동 보상**한다: 연락이 오면 확인 후 해당 Google 계정의
  `paid: true`를 KV에 직접 기록해 $3 잠금 해제를 무상 제공한다. 웹스토어
  업데이트 노트와 옵션 페이지에 안내 문구를 넣는다.
- 새 버전의 `savedWords` 이관은 위 "기존 저장분 이관" 절차를 따른다.

## 온보딩

키가 없으면 조회가 아예 되지 않으므로 옵션 페이지 첫 화면을 키 발급 안내로
바꾼다. **Gemini를 첫 번째로 제시한다** — 무료 등급이 있어 카드 등록 없이 키를
받을 수 있는 유일한 선택지다. Anthropic·OpenAI는 그 아래 둔다.

## 오류 처리

| 상황                           | 동작                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| API 키 미설정                  | 조회 시 옵션 페이지로 유도                                                            |
| 사용자 키 거부(401/403)        | 제공자 사유를 그대로 노출 + 키 확인 안내                                              |
| 사용자 키 429                  | 잠시 후 재시도 안내 (우리 한도가 아님을 명시)                                         |
| `/v1/me`·`/v1/words/list` 실패 | 로컬 미러로 동작. 서버 장애가 구매자를 잠그지 않는다                                  |
| `/v1/words/save` 실패          | 클라이언트 큐에 남겨 재시도. UI는 저장된 것처럼 선반영하되 실패 확정 시 되돌리고 알림 |
| 미로그인 상태에서 저장 시도    | 로그인 유도                                                                           |

## 테스트

- **불변 조건**: 워커 코드에 `api.anthropic.com`·`generativelanguage`·
  `api.openai.com` 문자열이 없고, `wrangler secret list`에 `CLAUDE_API_KEY`가
  없다. 조회 시 워커 로그에 요청이 찍히지 않는다.
- **결제**: 테스트 카드 1회 결제 → `paid: true` → 세 기능 해제.
- **환불**: 대시보드 환불 → `paid: false` → 기능 재잠금, 단어장 유지.
- **저장 한도**: 200개까지 저장, 201번째 거부·안내. 3개 삭제 후 다시 저장 가능.
- **이관**: sync에 60개(상세 포함) 있는 상태에서 첫 로그인 → 서버에 60개 업로드,
  로컬 미러 일치, sync 정리 확인.
- **다기기**: A에서 저장·복습 → B에서 같은 계정 로그인 → 단어·상세·복습 진도 동일.
- **복습**: 몰랐어요 → 같은 세션 재출제 + box 하락. 알았어요 3회 → box 3, 7일 뒤
  nextDue. 무료로 3장 후 잠금.
- **디바운스**: 단어 5개 연속 저장 → KV 쓰기 횟수가 묶여서 나감, 유실 없음.
- **BYOK**: Gemini 무료 키로 조회 동작 (프록시 제거 후).

## 남은 리스크

1. **Chromium·Brave에서는 로그인 자체가 불가능하다** (`chrome.identity` 없음 —
   오늘 확인). 이 설계에서는 결제뿐 아니라 **단어 저장도 로그인이 필요**하므로
   해당 브라우저 사용자는 조회만 가능하다. BYOK의 주 고객층(개발자 성향)과
   겹치는 제약이라 작지 않다. 해결책은 `launchWebAuthFlow` 전환이며 Google
   `sub`가 전역 고유값이라 기존 구매·단어장이 그대로 유지된다 — 별도 후속
   작업으로 남긴다.
2. **API 키 장벽.** 키를 발급받을 의향이 있는 사용자만 남는다. Gemini 온보딩
   품질이 사용자 수를 결정한다.
3. **$3 가치 입증.** 복습이 이 설계의 판매 핵심이다. Leitner 구현이 얇으면
   가격이 아니라 기능의 문제다.
4. **KV 쓰기 경합.** 같은 계정으로 두 기기에서 동시에 저장하면 마지막 쓰기가
   이긴다(단어장 전체가 값 하나이므로). 발생 빈도가 낮아 MVP에서는 수용하고,
   문제가 되면 단어별 키 분리로 전환한다.
